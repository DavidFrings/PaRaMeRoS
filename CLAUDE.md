# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Website for PaRaMeRoS (https://PaRaMeRoS.net). Two independently built parts, wired together by Docker Compose:

- `api/` — Rust (edition 2024, MSRV 1.92) Actix-web backend with Diesel (async via `diesel-async` + bb8) on PostgreSQL.
- `frontend/` — Vue 3 + TypeScript SPA built with Vite, served by nginx in production. UI text is German.

Both share a version number (`api/Cargo.toml` and `frontend/package.json`); publishing a GitHub release `v<semver>` triggers `.github/workflows/release.yml`, which opens a version-bump PR.

## Commands

Full dev stack (needs `.env`, copy from `.env.example`):

```sh
./dev.sh        # starts db+redis+api+frontend via docker-compose.dev.yml (API migrates itself)
```

API (run in `api/`) — CI runs these:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings   # lints: [lints] in Cargo.toml, incl. clippy::pedantic
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --all-features --locked
cargo +1.92 check --workspace --all-features --locked   # MSRV
cargo deny check                                       # replaces cargo audit; config in api/deny.toml
TEST_DATABASE_URL=postgres://... TEST_REDIS_URL=redis://... cargo test --locked -- --test-threads=1   # integration tests need real Postgres + Redis
diesel migration run --database-url postgres://...   # only to regenerate src/db/schema.rs (see diesel.toml)
```

DB/Redis tests skip (return early) without `TEST_DATABASE_URL` / `TEST_REDIS_URL`, and fail instead when `REQUIRE_TEST_DB` is set (CI's `api-test` sets it).

Frontend (run in `frontend/`, pnpm) — CI runs these:

```sh
pnpm install --frozen-lockfile
pnpm exec prettier --check src/   # `pnpm format` to fix
pnpm exec eslint . --max-warnings 0   # `pnpm lint` auto-fixes
pnpm run type-check               # vue-tsc
pnpm run build                    # type-check + vite build
pnpm dev
```

The API has integration tests (`api/tests/`); the frontend has none.

## Architecture

### API

- `src/lib.rs` builds an `Env` struct (DB pool, JWT secret/expiry, admin pass, CORS origins) from env vars and shares it as `web::Data<Env>`. Every handler is registered explicitly with `.service(...)` in `configure` in `src/app.rs` — new endpoints must be added both to `src/api/<area>/mod.rs` and to `app.rs`.
- In debug builds `.env` is loaded via `dotenvy`; in release all config comes from the environment (required vars panic if missing).
- `src/utils.rs` holds the shared plumbing: `HttpError` (implements `ResponseError`) with helpers `bad_request`/`internal_error`/`unauthorized`/`forbidden`, the `query!` macro (awaits a Diesel future and maps NotFound to 404 and other DB errors to a logged 500), `db(&env)` to get a pooled connection, `verify(&req, &env)` which validates the `Authorization: Bearer <JWT>` header and returns the `User`, and `authorize(&req, &env, perm)`/`require(&user, perm)` for permissions (`PERMISSIONS`), derived from the user's `role` (`normal`/`forest`/`super`) via `role_allows`; else 403. Every write handler checks a permission (see `api/README.md`).
- `src/db/schema.rs` is generated by Diesel from `migrations/`; models live in `src/db/models.rs`.
- Migrations in `migrations/` are embedded and run at API startup (no manual diesel step).
- Redis (`REDIS_URL`, optional, 2 s connect timeout) backs rate limiting and post caching; it fails open, so the API works without it.
- Post media goes through a validated pipeline (images become WebP/JPEG XL variants) into `UPLOAD_DIR` (default `/api/uploads`), a Docker volume that nginx in the frontend container also mounts and serves under `/uploads/`.
- `/sitemap.xml` (with hreflang) is generated from `SITE_URL` (required) and proxied by the frontend nginx.
- Registering a user requires the `ADMIN_PASS` env value in the request body. Route table: `api/README.md`.

### Frontend

- File-based routing via `unplugin-vue-router`: files in `src/pages/` become routes (`typed-router.d.ts` is generated). `[id].vue` = dynamic param, `[...404].vue` = catch-all.
- Runtime config is **not** baked in at build time: code reads `window.__ENV__` (`NAME`, `DESC`, `KEYWORDS`, `API`). In the container, `entrypoint.sh` writes `config.js` from `VITE_*` env vars before starting nginx. Use `window.__ENV__.API` as the API base URL (axios).
- `src/main.ts` sets up the router, `@unhead/vue` head/meta, PWA (`vite-plugin-pwa`), and `vanilla-cookieconsent` (only necessary cookies; the JWT is kept in the `auth_token` cookie via `vue3-cookies` and sent back as the `Authorization` header).
- `@` aliases `frontend/src`.

### Deployment

- `docker-compose.yml` (prod) / `docker-compose.dev.yml` (dev) run Chainguard Postgres, Redis (cache + rate limits), the API and the nginx frontend. Images are Chainguard-based (no shell, so no container healthchecks).
- `.github/workflows/cd.yml` builds and pushes per-arch (x86_64/aarch64) images for both parts on pushes to `main`, tagged with the version from `Cargo.toml` / `package.json`.
- Rate limits key on `X-Real-IP`. The host nginx must set it from a trusted source: `set_real_ip_from <Cloudflare ranges>; real_ip_header CF-Connecting-IP;` plus `proxy_set_header X-Real-IP $remote_addr;` (or firewall the origin to Cloudflare ranges). Never copy `$http_cf_connecting_ip` blindly: a direct hit on the origin could then spoof any IP.
- Prod compose binds db, API and frontend ports to `127.0.0.1` only.
- CI layout (`.github/workflows/ci.yml`): the `api` job calls `DavidFrings/rust-ci/.github/workflows/rust.yml@v1` (fmt, clippy, test without DB, doc, MSRV); its summary job `api / result` is the required check. `msrv` there must match `rust-version` in `api/Cargo.toml`. `api-test` runs the integration tests with Postgres/Redis services. Frontend and Docker jobs are separate.
- `security.yml` runs cargo-deny via rust-ci `rust-security.yml@v1` on changes to `api/` Cargo files or `deny.toml`, and weekly (Monday). Advisory findings fail only the weekly run, not PRs (template behaviour, decided); licenses/bans/sources fail PRs.
- `scripts/github-setup.sh` (repo settings, labels, merges required checks into the "Main" ruleset) is run by hand only, never from CI.
